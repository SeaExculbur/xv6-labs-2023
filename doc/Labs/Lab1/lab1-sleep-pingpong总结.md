# xv6 Lab1 前两题总结：sleep + pingpong（踩坑与知识点）

> 范围：MIT 6.1810 xv6-labs-2023 lab1（util lab）前两题
> 原则：只记录做题需要的知识；不深入内核实现细节，必要的内核概念（隔离、调度、缓冲）点到为止

## 0. 每道题的固定工作流（先背下来）

```
① 写代码：在 WSL 里 ~/xv6-labs-2023/user/xxx.c（VS Code 编辑，Windows 的 E:\My_project\xv6 副本只读）
② 登记：把 _xxx 加进 Makefile 的 UPROGS 列表（照抄相邻行格式，行尾 \ 不能丢）
③ 编译启动：make qemu（编译错误会停在这里，红字指向出错文件和行号）
④ 测试：xv6 里运行程序 → Ctrl+a x 退出
⑤ 评分：./grade-lab-util xxx （只测本题）或 make grade（测全部）
```

**三条铁律**：
1. **xv6 只运行"上次编译进镜像"的版本**：改完代码必须 `make qemu` 重启才生效，编辑器里改了不编译 = 没改
2. **xv6 是另一个操作系统**：它的 $ 和 Ubuntu 的 $ 是两回事；xv6 里只有编译进 UPROGS 的程序
3. **xv6 没有信号机制**：前台程序卡死（死循环/超长 sleep）无法用 Ctrl+C 杀掉，只能 `Ctrl+a x` 重启 xv6

## 1. 通用知识点（两道题都用到）

### 1.1 用户程序骨架

```c
#include "kernel/types.h"    // 基础类型（必须先于 user.h）
#include "user/user.h"       // 系统调用 + 库函数声明（依赖 types.h）

int main(int argc, char *argv[])
{
    ...
    exit(0);                 // 显式退出；错误路径用 exit(1)
}
```

### 1.2 argv 的结构（★ 最容易错）

```
输入 sleep 10 →  argc = 2
  argv[0] = "sleep"   ← 程序名，不是参数！
  argv[1] = "10"      ← 第一个参数
  argv[2] = NULL      ← 数组结束标记（空指针）
```

**坑（我踩的）**：`while(argv[i])` 从 i=0 遍历会把程序名也当参数处理（`atoi("sleep")`=0，碰巧无害——程序名能解析出非零数字就出大事）。遍历参数永远从 i=1 开始。

### 1.3 exit 与 main 的关系

- xv6 用户程序入口是 `_main`（在 user/ulib.c），它调 main() 后自动 `exit(0)` —— main 忘了 exit 不会跑飞（有兜底）
- 但兜底只给 exit(0)：**错误路径必须自己 exit(1)**（让 wait 的父进程知道出错了）
- 官方建议 main 结尾显式 exit(0)，养成习惯

### 1.4 编译纪律

- xv6 编译选项 `-Wall -Werror`：**警告 = 错误**。声明了不用的变量直接编译失败（pingpong 第一版踩过：`char *buff[4]` 没用上）
- 未使用变量的报错样式：`error: unused variable 'buff'`

### 1.5 调试手段

- xv6 里 `Ctrl+P`：打印当前所有进程（pid、状态、名字）
- `kill <pid>`：杀掉指定进程（kill 是 xv6 系统调用之一）
- 前台程序不结束 = shell 阻塞在 wait，$ 不出现——正常现象，程序自己能退出才行

## 2. sleep 题

### 题目
程序暂停用户指定的 tick 数。tick = xv6 内核时间单位（两次时钟中断间隔，约 1/10 秒）。代码放 user/sleep.c。

### 知识点

| 点 | 内容 |
|----|------|
| argc 检查 | `argc < 2`（没传参）打印 usage 报错退出 |
| atoi | 字符串转 int。**只解析十进制正整数前缀**：`"10"→10`、`"12ab"→12`、`"abc"→0`、`""→0`；无负号、不跳空格 |
| sleep(整数) | 暂停 n 个 tick，sleep(0) 立即返回 |
| 错误路径 | `exit(1)`，别 exit(0) |

### 我的坑
1. **`while(argv[i])` 从 0 开始**：把程序名也睡了一遍（sleep(atoi("sleep"))=sleep(0)）。碰巧无害，但暴露"argv[0] 不是参数"的理解误区
2. **exit 后写 return**：死代码。exit 不返回，return 永远不会执行；而且会误导自己"main 可以返回"

### 参考答案形态

```c
if(argc < 2){
    printf("usage: sleep ticks\n");
    exit(1);
}
sleep(atoi(argv[1]));
exit(0);
```

### 延伸：别人家的防御（社区代码）
社区有人先手动校验 argv[1] 是否全为数字再 atoi（防 `sleep abc` 静默当 0 睡）。官方 grader 不测非法参数，属于超出需求的防御性编程——可选，不是必须。但要知道 atoi 的宽容是"静默截断"，不是报错。

## 3. pingpong 题（管道入门）

### 题目
父进程和子进程通过管道"乒乓"一个字节：子进程收到后打印 `自己的pid: received ping` 并回传；父进程收到后打印 `自己的pid: received pong`。

### 3.1 管道的心智模型（★ 核心）

**管道 = 内核里一块 512 字节缓冲 + 两个文件描述符**。一个进程往里写（写端），另一个从里读（读端），像邮箱：

```
write(p[1], ...)  = 投信进邮箱（缓冲有空间就立即返回，不需要收信人在场）
read(p[0], ...)   = 取信（有信就取走；邮箱空就睡着等，直到有信或所有写端关闭）
```

三个关键性质：
1. **单向**：数据只从写端流向读端 → 双向通信要**两根管道**
2. **fork 复制 fd 表**：管道在 fork 前创建，父子各持一份 fd 指向**同一个内核管道对象**
3. **阻塞语义**：读空管道会睡（xv6 无非阻塞模式）；写端全关后 read 返回 0

### 3.2 区分多个管道靠 fd 号，不是 pipe 的返回值

```c
int pipe(int p[2]);   // 返回 0 成功 / -1 失败，仅此而已
```

管道身份在**传入数组里**：pipe 调用后 p[0]=读端 fd、p[1]=写端 fd。内核按"最低未使用 fd"分配（0/1/2 是标准输入/输出/错误，从 shell 继承）。两次 pipe 后假设 p1={3,4}、p2={5,6}——之后操作管道全部靠这些 fd 号，它们是唯一手柄。（pipe 不给两个 fd 只能靠数组输出，和 wait(&status) 是同一个"输出参数"模式）

### 3.3 fork 与管道创建顺序（★ 最关键的坑）

**两根管道都必须写在 fork 之前！**

```
✗ 错误流程：
   fork() → 子进程里 pipe() → 子往新管道写 → 父进程读？
   父进程的 fd 表里根本没有这根管道（fork 已经发生过了）→ 读不了

✓ 正确流程：
   pipe(p2c); pipe(c2p);   // 都在 fork 前：fork 把两组 fd 复制给子进程
   fork();                 // 之后父子各持有两根管道的全部 4 个 fd
```

### 3.4 read 的三个真相（★）

1. **返回实际读到的字节数 n**：n 不是"识别缓冲区"得出的，是内核从数据源（文件偏移/管道存量）拷贝时数的数。请求 8 但管道只有 4 → 返回 4
2. **不补 \0**：read 从 buf[0] 开始覆盖写 n 个字节，buf[n..] 是没碰过的原垃圾。它不判断垃圾和数据——它只从开头写，写多少算多少（倒水类比：n 是水面刻度）
3. **读空管道会阻塞睡在"数据可用"事件上**：子进程先执行 read 时管道空 → 睡；父进程 write 放入数据那一刻内核唤醒它。子进程等的是"缓冲从空变非空"这个条件，**不是等父进程这个实体**（生产者-消费者模型）

### 3.5 字符串通过管道传递的正确姿势

```c
char *msg = "ping";
write(p[1], msg, 4);     // ✓ 传内容：msg 是字符串首地址（"ping" 的 p 的位置）
write(p[1], &msg, 4);    // ✗ 我踩的坑：&msg 是指针变量自身的地址（8 字节里前 4 个）
                         //   管道里流的变成"地址值字节"→ 接收端打印出乱码 �
```

接收端处理 \0（read 不给 \0，%s 靠 \0 停，垃圾区没有 0 就会越界打印）：

```c
char rec[8];
int n = read(fd, rec, sizeof(rec) - 1);   // 请求 = 缓冲大小 - 1（永远安全）
rec[n] = 0;                               // 在水面位置手动钉 \0
printf("%s", rec);                        // 打印到 \0 停
```

### 3.6 输出格式（grader 精确匹配）

grader 的正则：`^\d+: received ping$` 和 `^\d+: received pong$`，所以：

1. **拼写必须 exact**："received"（我拼成 recevied 会 FAIL）
2. **不能带尖括号** `<4>: received ping` ✗；`4: received ping` ✓
3. pid 用 `getpid()` 打**自己的** pid（子打子的、父打父的）
4. 打印**固定文本**"received ping/pong"即可——题目传的字节只是信号，内容无所谓（官方 one byte 设计就是为了不让你在内容上花心思）。如果设计成"打印收到的内容"，内容必须恰好是 ping/pong 才能过 grader

### 3.7 参考答案骨架

```c
#include "kernel/types.h"
#include "user/user.h"

int main() {
    int p2c[2], c2p[2];
    pipe(p2c);   // 父 → 子（fork 前！）
    pipe(c2p);   // 子 → 父（fork 前！）

    int pid = fork();
    if(pid == 0){
        char buf;
        read(p2c[0], &buf, 1);                // 等父发来（空管道会睡）
        printf("%d: received ping\n", getpid());
        write(c2p[1], &buf, 1);               // 回传
        exit(0);
    } else {
        char buf = 'x';                        // 内容无所谓
        write(p2c[1], &buf, 1);
        read(c2p[0], &buf, 1);                 // 等子回传
        printf("%d: received pong\n", getpid());
        wait(0);
        exit(0);
    }
}
```

### 3.8 没踩但要知道的坑：close 多余端

fork 后父子各握 4 个 fd（2 管道 × 2 端），各只用 2 个。多余的写端不关，最坏情况：**读空管道时只要还有任何写端开着（哪怕自己手里那份），read 永远阻塞**（它等"数据可能再来"，不会返回 0）。进程 exit 会自动关 fd，所以小程序不 close 能跑——但养成习惯：每个进程 close 自己用不到的三个端。

## 4. 速查：这次踩过的全部坑（按发生顺序）

| # | 坑 | 后果 | 教训 |
|---|----|------|------|
| 1 | Makefile 没登记 UPROGS | xv6 里 `exec xxx failed` | 新程序先登记再编译 |
| 2 | 声明未使用的变量 | -Wall -Werror 编译失败 | 删掉没用上的声明 |
| 3 | 前台程序无限睡眠 | $ 消失，键盘无响应 | xv6 无信号，只能 Ctrl+a x 重启；程序必须能自己退出 |
| 4 | while(argv[i]) 从 0 遍历 | 把程序名也处理了 | argv[0] 是程序名，参数从 1 开始 |
| 5 | 只建一根管道 | 有去无回，ping 完没 pong | 单向管道，一来一回要两根 |
| 6 | read 到 &pid 覆盖变量 | pid 被当缓冲毁了 | 缓冲用独立数组，别拿业务变量当缓冲 |
| 7 | write(&data, 4) 传指针地址 | 管道里流的是地址字节 → 乱码 � | write 传内容首地址（变量名），不是 &变量 |
| 8 | "recevied" 拼错 / 带 <> | grader 正则不匹配 | 输出格式精确对照 grader 期望 |
| 9 | rec[4] 无 \0 直接 %s | 越界打印垃圾 | read 后补 \0，请求大小 = 缓冲 - 1 |
| 10 | 管道在 fork 后创建 | 父进程没有新管道的 fd | 所有管道必须在 fork 前 pipe |
| 11 | exit(1) 后面写 return | 死代码 | exit 不返回；错误用 exit(1) |

## 5. 一句话心智模型收尾

- **sleep 题**：xv6 程序 = 头文件 + main(argc, argv) + exit；argv[0] 是程序名
- **pingpong 题**：fd 表项指向内核对象（管道/文件）→ fork 复制 fd 表 → 父子共享管道 → read/write 操作 fd；**改"编号指向什么"就能让程序的行为改变**（重定向同款思路）
- **所有系统调用**：返回 0/-1 报告成败 + 输出参数（数组/指针）带结果；错误时 -1，不设 errno
